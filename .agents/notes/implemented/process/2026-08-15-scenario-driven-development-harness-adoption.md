# Agent Note: 以使用场景驱动开发 Harness 研究与采用

Status: implemented

## Problem

从单个历史 commit、PR 或事故开始严密还原，能够提高历史解释的可信度，但会把大量精力放在证明过去发生了什么。当前研究的直接目标不只是总结 DSH 的开发经验，还要理解各类 Harness 如何介入研发，并把成熟部分尽快提取成可以在本仓库和其他仓库使用的工作流、Skill、脚本或规则。

如果完整历史还原成为每项研究的入口，首个可用 Harness 会被证据考据、时间线分歧和深度机制分析推迟。相反，只复制历史 Skill 或脚本又会携带 DSH 路径、分支和产品命令假设，得到表面可用但无法安全采用的资产。

## Decision

研究采用“场景理解、快速提取、实际使用、反馈修正、按需深挖”的主线。研究单位是 Harness 使用场景，例如任务进入、规则读取、变更范围识别、验证选择、提交与推送、决策记录、PR 评审、文档与翻译、证据保存和事故反馈。历史现场是解释约束与失败方式的证据，不是所有研究的必经入口。

每个场景同时回答两类问题：Harness 何时介入、接收什么输入、执行什么动作、如何反馈、产生什么结果；现有材料中哪些能够直接使用、轻量适配、只作研究证据或需要深入分析。研究默认先交付能够投入使用的最小切片，再由真实使用中的问题决定是否增加分析深度。

### 场景产出

每个场景使用一份简短记录说明：触发条件、目标、参与者、输入、动作、反馈、输出、不使用时的失败方式、现有资产、采用步骤和适用限制。可以立即复用时，同一检查点交付对应的 Skill、脚本、规则片段、模板或配置，并提供安装、调用、验证和移除方式。

场景资产按以下等级处理：

- **L1 — 直接可用**：当前资产已脱离产品运行面，只需准确说明调用方式。
- **L2 — 轻量适配**：机制可复用，但需要移除 DSH 路径、命令、分支或平台假设。
- **L3 — 研究材料**：具有经验价值，但产品绑定深或缺少独立运行条件，当前不工具化。
- **L4 — 按需深挖**：存在证据冲突、高风险副作用、无法解释的约束，或实际试用失败，需要恢复历史现场或执行对照验证。

等级不永久固定。L1、L2 通过实际使用证明价值；失败后可以降级或进入 L4。L3 只有在具体使用需求出现后才重新评估，不能因为已经保留就自动通用化。

### 深度与证据

快速理解不能把推断写成事实。产品事实仍从 [source lock](../../../../research/source-lock.json) 固定的官方提交核验；历史材料与当前仓库规则分开。场景记录应指出直接证据、合理解释和未知项，但默认不要求建立完整历史时间线。

只有出现以下条件才进行深度现场还原：材料互相冲突；无法解释一项会影响安全使用的约束；提取后的行为与预期不符；涉及破坏性 Git、并发、安全、持久化或远端状态；准备删除、替换或提升为通用方法。深挖可以使用多个独立 subagent、固定 checkout 和最小重放，但 Agent 一致意见不提高证据等级。

### 并行推进

默认让 subagent 并行负责不同 Harness 场景，并使用相同的场景产出字段和复用等级。主线程负责完整生命周期地图、跨场景接口、重复能力、采用顺序和唯一正式记录。subagent 草稿不直接成为仓库权威，也不并发修改同一正式文件。

只有 L4 或高风险机制才默认采用同一现场的独立还原和证据审计。普通 L1、L2 场景不为了方法校准重复分析。

最小 Harness v0 的目标是让 Agent 能读取仓库规则、识别真实变更范围、选择与改动对应的验证、留下必要决策证据，并安全进入 commit、push 和 CI。H0 可以调整其具体组成，但不能用完整平台建设替代这条可观察结果。

本决定取代“所有研究默认从现场还原开始”的做法，并吸收其仍有效的边界：历史主张需要固定来源，推断不能伪装成事实，产品源码只在临时 checkout 中用于核验或重放，不为研究恢复完整 monorepo。被取代的记录退出活跃语料，由 Git 历史追溯。

## Alternatives considered

- **所有场景先完成同现场双 Agent 盲还原**：适合高风险机制审计，但普通场景会重复证据整理并推迟可用资产，因此仅用于 L4。
- **继续只保存案例，由使用者自行复制**：最省维护工作，但 DSH 假设不会被明确移除，无法证明资产能独立使用。
- **一次性设计完整通用 Harness**：能够得到统一结构，但会在真实使用前提前决定接口和能力，重现本研究试图避免的平台建设负担。
- **只提炼经验，不交付资产**：可以快速形成报告，但无法通过实际使用检验理解，也不能满足快速投入使用的目标。
- **直接复制全部历史 Skills 与脚本**：文件数量增加最快，但会重新引入产品绑定、失效命令和自动调用风险。

## Consequences

- 第一阶段更快产生可调用的 Harness，同时接受对历史动机只有必要深度的理解。
- 并行 subagent 默认扩大场景覆盖；一致性审计保留给高风险或出现争议的场景。
- 每项研究都需要明确采用结果，避免只增加说明文档而没有实际使用者。
- 实际使用可能推翻历史材料给出的价值判断；此时以当前可观察结果调整等级和资产。
- 深度研究仍可进行，但必须由风险、失败或采用决策触发，并说明它将改变什么。
